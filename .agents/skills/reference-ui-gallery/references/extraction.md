# UI 추출

## 관찰 범위

대상 화면의 대표 작업, 상태, 화면 크기, 테마와 원본 버전을 먼저 기록한다. 화면 한 장에서 앱 전체의 디자인 시스템을 추정하지 않는다.

1. 실제 렌더링과 상호작용을 관찰한다. 웹은 사용 가능한 브라우저 검사 기능, 네이티브 앱은 화면 캡처/접근성 트리와 제공된 앱 자료를 사용한다.
2. 접근 가능한 코드/CSS/폰트/자산/토큰 선언을 함께 확인한다. REA가 적합하면 현재 도구의 도움말과 기능을 확인해 분석한다. REA를 필수 의존성이나 유일한 수단으로 두지 않는다.
3. 번들 선언과 현재 화면의 실제 사용을 구분한다. 미사용 코드나 실험용 스타일은 화면에서 확인할 때까지 원본의 기본 규칙으로 채택하지 않는다.
4. 추출 결과에 출처 위치, 버전, 방법, 근거를 연결한다. 큰 원본 dump는 별도 로컬 자료로 보관하고 공개 항목에는 필요한 근거만 옮긴다.

도구가 네이티브 뷰에 닿지 못하거나 분석 크기 한도에 걸리면 해당 한계를 기록한다. 다른 허용된 도구나 범위를 좁힌 분석으로 진행하고, 확인할 수 없는 값은 추정으로 남긴다.

## 근거 분류

| 분류 | 뜻 |
|---|---|
| `observed` | 화면/동작 또는 소스 선언에서 직접 확인한 사실. 어느 쪽인지 방법에 적는다. |
| `measured` | 뷰포트/테마 등 조건을 고정해 측정한 값. |
| `inferred` | 관찰 결과를 바탕으로 추정한 규칙. |
| `proposed` | 원본에 없거나 확인하지 못해 새 화면을 위해 제안한 규칙. |

스크린샷만 있으면 정확한 폰트, 숨은 상태, breakpoint, blur/합성 방식은 확정하지 않는다. 실제 코드가 있어도 렌더링과 일치하는지 별도로 비교한다.

## 디자인 규칙으로 정리

- 토큰은 원시 값과 의미를 구분한다. 같은 색도 본문, 비활성, 경계선 역할을 구분하고 토큰 참조 관계를 보존한다.
- 컴포넌트는 구성 요소, 크기/밀도, 콘텐츠 제약, 상태 전환, 키보드/포커스 동작을 기록한다.
- 레이아웃은 열과 패널의 관계, 최소/최대 크기, 정렬, 콘텐츠가 늘거나 좁아질 때의 변화를 기록한다.
- 효과는 토큰 값과 합성 조건을 함께 기록한다. 특정 CSS 구현을 모든 플랫폼의 필수 스택으로 삼지 않는다.

## 투명/글래스 표면

배경 이미지와 색, 표면 불투명도, backdrop blur, 안쪽 테두리, 바깥 윤곽, 그림자, 반사 레이어를 각각 확인한다. 레이어 순서와 중간 요소의 불투명 배경/stacking context가 합성을 바꾸는지도 확인한다.

밝은/어두운 배경, 표면 중첩, 팝오버/입력창에서 같은 규칙이 유지되는지 비교한다. 투명 효과를 끈 경우의 표면과 대비를 기록한다. 일반 글래스와 실험용 Liquid Glass가 함께 있으면 서로 다른 변형으로 표시한다.

브라우저 확장, 강제 다크 모드, OS 효과가 원본과 프로토타입에 다르게 적용되는지 확인한다. 원본과 다른 환경으로 비교했다면 그 차이를 검증 기록에 남긴다.
