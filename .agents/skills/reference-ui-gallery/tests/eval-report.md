# 경량 평가 기록

대상: reference-ui 초기 후보. Codex의 새 컨텍스트 worker를 사용했고 두 실행 arm의 설정 모델은 동일하게 gpt-6.1-sol/high였다. 자료는 CSS 선언만 있는 합성 fixture이며 실제 앱 품질 평가가 아니다.

## 라우팅

별도의 description-only 컨텍스트에서 eval-cases의 명확한 호출과 다른 표현은 호출, 작은 hover 버그 수정은 비호출로 판정했다. 세 기대 결과와 일치했다. 첫 실행 worker는 본문까지 읽었으므로 그 worker의 판정을 blind 라우팅 근거로 사용하지 않았다.

이 검사는 description 선택 판단이다. 각 CLI의 실제 자동 호출이나 기본 프롬프트 노출을 증명하지 않는다.

## 같은 입력의 on/off 비교

| 항목 | 스킬 없음 | 스킬 사용 |
|---|---|---|
| CSS 선언과 미확인 동작 구분 | 보존 | 보존 |
| 새 설정 화면 규칙 | 제안으로 표시 | 제안으로 표시 |
| 저장 구조 | 자체 README/CSS/JSON 구조 | DESIGN.md/tokens.json/reference.json 공통 계약 |
| 토큰 | 원본 값 11개를 자체 형식으로 정리 | 원시 값 9개와 의미 참조 4개를 분리 |
| 준비 완료 검사 | 별도 자동 게이트 없음 | validate 통과, --ready는 new_screen 미검증으로 차단 |
| 기본 갤러리 노출 | 수동 목차 | 초안은 기본 catalog에서 제외 |

기본 모델도 사실과 추론을 구분했다. 관찰된 추가 가치는 공통 저장 계약, 토큰 참조와 자동 검증, 초안 노출 제어다. 시각적 우열이나 디자인 개선은 이 평가에서 주장하지 않는다.

## 추측과 검증 범위

slug와 토큰 이름, 같은 값의 의미별 별칭은 작업자가 정했다. 원본에 실제 공유 토큰이 있다고 주장하지 않았다. 원본 앱, 스크린샷과 실행 환경이 없어 시각/상태/반응형/접근성/새 화면 실행은 not-run으로 남겼다.

로컬 도구의 14개 행동 테스트는 격리 설정, 기존 파일 보존, 잘못된 JSON/필드 타입, 원격 불일치, 경로 이탈, 토큰 누락/순환 참조, 준비/공개 기록 게이트를 통과했다. 잘못된 필드 타입이 내부 예외로 끝나는 실패를 재현한 뒤 설명 가능한 오류로 수정했다.

공식 install-skill.sh를 격리된 전역 설치 경로에서 실행해 원본 복사와 Claude/flat alias/Aside 내용물 링크를 확인했다. 실제 사용자 전역 경로의 발견/명시 호출 검증은 설치 작업에서 별도로 수행한다.

## 공개 경계 리뷰 후 확인

출처 URL에 인증정보가 있으면 초안 저장 전과 기존 항목 검증에서 모두 거부하도록 수정했다. 합성 userinfo/민감 query 재현과 기존 공개 항목 차단을 포함한 16개 행동 테스트를 통과했고 재리뷰에서 추가 finding은 없었다.

## 갤러리 자동화 확장

공개 파일 목록, 로컬 경로/깨진 링크, 기존 출력 보존, HTML 데이터 이스케이프, 토큰 CSS 생성, 스킬 설치 없이 실행되는 bundled builder, 생성물 수정 충돌, 비적용 publish 계획, CI의 초안 배포 거부를 추가 검사한다. 실제 GitHub Actions/Pages 실행 결과는 해당 발행의 receipt와 build.json commit으로 확인한다.

## 갤러리 테마 확장

동일한 저장소 CSS 입력으로 변경 전에는 테마 파일이 출력되지 않고 비공개 경로 검사가 생략되는 실패를 확인했다. 변경 후에는 테마 복사/manifest 포함/원본 보존, 비공개 경로/누락 자산/symlink 차단, 비적용 publish 계획을 포함한 29개 행동 검사가 통과했다. description과 호출 정책은 바꾸지 않았다.

실제 레퍼런스의 토큰과 공개 자산을 연결한 갤러리에서 밝은/어두운 테마, 단색 전환과 설정 유지, 검색/초기화, 플랫폼/태그 필터, 문서 링크를 브라우저로 확인했다. 320/390/768/1440 CSS px에서 가로 넘침을 검사하고 화면을 캡처해 검수했다. 첫 캡처에서 배경 URL이 소비하는 CSS 위치로 해석되는 오류를 발견해 수정했고, 실제 이미지 로딩 검사를 추가해 20개 브라우저 검사를 통과했다. 실기기와 전체 접근성 감사는 이 확인에 포함하지 않는다.

## 디자인 시스템 재사용과 원본 복제 구분

채팅 앱의 글꼴/간격/의미 색상/반투명 표면과 배경 사진을 입력으로, 갤러리 재사용, 원본 화면 복제, 버튼 hover 수정의 세 요청을 별도 Codex 컨텍스트에서 평가했다. 스킬 본문을 읽지 않은 baseline은 갤러리에도 배경 사진을 적용하겠다고 답했다. 수정한 본문을 읽은 실행은 갤러리의 콘텐츠 위계에 맞춰 토큰과 컴포넌트만 연결하고 원본 사진과 채팅 배치는 제외했다.

원본 복제 요청에서는 두 실행 모두 사진과 배치를 포함해 비교하며, 국소 hover 수정에서는 둘 다 스킬을 선택하지 않았다. 두 실행 모두 구체적인 화면 치수, 색상값과 갤러리 배치는 추가 근거가 필요한 것으로 남겼다. 이 평가는 가상 입력의 판단 비교이며 다른 런타임의 자동 호출이나 실제 시각 품질을 증명하지 않는다. 실제 갤러리 수정은 중립 배경, 원본 토큰 연결, 검색/필터와 화면 크기를 브라우저로 별도 검증한다.

## 전체 프로젝트 스킬 배포

같은 프로젝트 설치 입력에서 변경 전에는 전체 스킬 발행 옵션이 없었고, 파일을 넣어도 갤러리와 스킬 경로의 무조건 분리 검사로 실행이 거부됐다. 변경 후에는 표준 프로젝트 스킬 위치만 허용한다. 전체 묶음을 다른 경로로 옮기고 개인 설정을 잘못된 JSON으로 둔 상태에서도 저장소 래퍼의 빌드가 통과했다. 기존 전역 설치 경계, symlink/수동 편집 차단, 다음 발행의 묶음 보존을 포함한 행동 검사 34개가 통과했다.

공식 프로젝트 설치기로 상대 Claude/GJC 링크를 만들었다. 동일 묶음의 격리된 Git 복제본에서 Claude Code, Codex, GJC 각각의 명시 호출이 프로젝트 본문과 설정 참조를 읽고 실제 `--help`, `catalog --public`를 실행했다. 세 런타임의 도구 출력에서 같은 공개 항목을 확인했다. Codex 기본 프롬프트에는 프로젝트 이름과 경로가 노출됐고 GJC는 source=project로 발견했다. 자동 선택과 Cursor/Grok의 실제 호출은 이 검사에 포함하지 않는다.

소스는 검토한 자체 스킬 파일 목록으로 한정하며 개인 설정과 다른 스킬은 묶지 않는다. 새 네트워크 목적지나 권한을 추가하지 않고 기존 GitHub/Pages 발행 경로를 사용한다. 실제 사용자 경로와 네이티브 실행 원문은 배포 묶음에 포함하지 않는다.

## REA, Taste, prototype 연결

수정 전후의 별도 Codex 컨텍스트에 동일한 다섯 요청을 주었다. 기존 지침은 ASAR 명령, 앱용 Taste 하위 스킬, 고정 브랜드의 방향 생성 인자와 비교안 수를 추측 영역으로 남겼다. 수정본은 REA의 `analyze_javascript_application`, 앱의 `redesign-existing-projects`, 마케팅 페이지의 기본 Taste v2와 `draw.mjs --keep palette,type` 경로를 구체적으로 선택했다. 두 실행 모두 원본 규칙/기존 스택 보존, 미설치 도구의 실행 주장 금지와 작은 hover 수정의 비대상 판정을 유지했다.

실제 REA MCP로 합성 JavaScript 디렉터리를 정적 분석해 11개 노드와 13개 관계를 받았다. 인자에 의존하는 gap/radius는 unknown으로 남아 실제 측정값과 구분했다. 설치된 Taste의 draw 스크립트에서 세 방향을 얻고 선택한 방향을 색/서체 유지 조건으로 구체화했다. 분석 그래프와 방향 제안의 실행 확인이며, 실제 앱의 시각 검증이나 Taste inspector 통과를 뜻하지 않는다.

REA의 현재 도구 스키마, 설치된 Taste 기본/기존 앱 개선 스킬, prototype의 UI 비교 절차와 공식 저장소를 확인해 연결 기준을 작성했다. 새 참조 두 개는 전체 프로젝트 패키지의 파일 목록에 포함한다. 외부 도구를 새로 설치하거나 권한을 넓히지 않았으며 분석 원문과 실행 경로는 배포하지 않는다.

## 제품 구현과 갤러리 관리 경계

일반 제품에 디자인을 적용하기만 하는 요청을 제외하고, 패키지 안의 재사용 검증과 갤러리 홈페이지/테마 관리를 명시했다. 기존 Vue 평가 사례는 패키지 미리보기와 보관을 포함하는 요청으로 맞췄다. 별도 제품 적용과 갤러리 저장소 변경의 경계 사례를 추가했다.

실제 Codex 프롬프트에서 추출한 186개 description에 수정 전후 두 스킬을 각각 연결해, 서로 다른 새 컨텍스트에서 같은 13개 요청을 비교했다. 수정 전에는 제품 재사용과 갤러리 화면 변경에 담당 중복이 있었고, 수정 후에는 별도 제품 구현과 갤러리 저장소 관리가 구분됐다. 이는 설명 기반 선택 평가이며 전체 런타임의 자동 호출 성공을 뜻하지 않는다.

별도 새 컨텍스트에서 두 경계 요청의 본문 절차를 읽었다. 제품 적용은 갤러리 설정/보관을 시작하지 않았고, 갤러리 수정은 전체 워크플로와 gallery.css/생성물 소유권을 유지했다. 기존 갤러리의 --help, doctor, catalog --public을 실제 실행해 모두 종료 코드 0을 확인했다. 이때 설치된 묶음은 0.5.0이었으므로 0.5.1 반영 증거로 표시하지 않았다. 변경 스킬의 정적 검사와 기존 행동 테스트 34개가 통과했다.

최종 배포 검토에서 본문과 발행 manifest의 버전 차이를 발견했다. 실제 묶음을 생성해 두 버전을 대조하는 회귀 검사가 0.5.0/0.5.1 불일치에서 실패하는 것을 먼저 확인하고, 발행 버전을 0.5.1로 맞췄다. 이 검사를 포함한 35개 행동 테스트가 통과했다.
