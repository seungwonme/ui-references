# 공개본 검증

Aside의 Chromium 브라우저에서 공개용 재구현을 실행했다. 자동 동작/구조 확인 39개를 통과했으며 결과는 browser-checks.json에 있다. 밝은/어두운 화면과 모바일/데스크톱 캡처를 직접 확인했다.

## 새 화면 재사용

settings.html은 추출 당시 없던 새 설정 화면이다. 대화 화면과 같은 tokens.json에서 생성한 CSS를 사용한다. 테마, 표면, 밀도, 토글, 모션 축소가 화면에 반영된다. 저장 중, 오류와 입력 보존, 재시도 성공, 되돌리기를 확인했다. 실제 설정 API에는 연결하지 않는다.

## 원본 근거와 시각 비교

CSS/JavaScript에서 얻은 선언과 A 기준안의 글꼴, 표면, 사이드바 폭, 공통 blur를 대조했다. 공통 blur는 8px, A의 재구현 사이드바 폭은 280px였다. B/C의 구조와 Liquid 효과 이식은 문서화한 변형이다. 공개용 사진 교체 후 어두운 Liquid 패널의 글자 대비를 위해 base tint를 추가했고 이를 proposed로 기록했다.

실제 네이티브 앱의 픽셀 동일성, 창 프레임과 운영체제의 재질 합성은 미검증이다. 이 기록은 브라우저 재구현과 출처 선언의 비교를 뜻한다.

## 상태와 반응형

빈 입력의 전송 비활성, 입력 후 활성, 진행 중, 오류, 입력 보존, 재시도를 확인했다. 390/768/1280 CSS px의 실제 emulated viewport에서 가로 넘침이 없었으며 입력과 전송 버튼이 뷰포트 안에 있었다. 설정 화면도 세 폭에서 가로 넘침이 없었다. 물리적 iPhone/Android 기기 테스트는 수행하지 않았다.

## 접근성 범위

설정 입력의 레이블, 모바일 메뉴의 본문 포커스 차단과 호출 버튼으로의 복구, 모션 축소 선택을 실행 확인했다. 밝은/어두운 화면의 읽기 상태를 시각 검토했다. 전체 WCAG 적합성이나 모든 배경 조합의 대비 인증을 주장하지 않는다.

## 실행과 자산

대화 화면, 설정 화면, 갤러리에서 uncaught error와 unhandled rejection이 없었다. 갤러리 검색의 일치/빈 상태와 미리보기/디자인 문서/토큰/메타데이터 링크를 확인했다. 폰트와 배경은 로컬 정적 자산으로 제공한다.

미리보기 캡처는 명시적 viewport clip을 사용한 Chromium 캡처다. 일반 캡처 wrapper의 타일 반복 현상은 DOM 중복이 아니었으며, 해당 이미지는 공개 근거에서 제외했다.
